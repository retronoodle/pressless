- [x] 1.1 Extract a private `fetchJson(string $path): ?array` helper in `src/Update/ReleaseEndpointClient.php` that runs the cURL request (timeout, user-agent, accept header, 2xx check, JSON decode) and returns the decoded body or `null` on any failure. Refactor `fetchLatest()` to use it.
- [x] 1.1a Extend `fetchLatest()`'s return array to also capture `published_at` (ISO-8601 string) from the response: `['latest' => string, 'url' => string, 'published_at' => string]`. A response missing `published_at` (or where it isn't a non-empty string) is now treated the same as a missing `tag_name`/URL — the whole call returns `null`. Update `tests/Unit/Update/ReleaseEndpointClientTest.php`'s existing fixtures to include `published_at` in the fake response body and assert it's present in the returned array; add a new case asserting a response missing `published_at` returns `null`.
- [x] 1.2 Add `fetchReleaseByTag(string $tag): ?array` that hits `releases/tags/<tag>` via the new helper and returns `['version' => string, 'published_at' => string, 'download_url' => string|null]` or `null` on any failure (404, non-2xx, malformed JSON, missing `tag_name`, missing `published_at`, no usable URL). Empty `$tag` or unconfigured `githubRepo` → `null`. The caller is responsible for passing a GitHub-tag-shaped string (see 3.2 — the installed version's leading `v` is re-added by the caller); this method does not itself add or strip a `v` prefix.
- [x] 1.3 Add unit tests in `tests/Unit/Update/ReleaseEndpointClientTest.php`: 200 with full body (parses `version`, `published_at`, `download_url`), 404 → `null`, 200 with malformed JSON → `null`, transport failure → `null`, missing `published_at` → `null`, no usable URL → `null`, empty repo → `null`.

## 3. Extend `UpdateChecker`

- [x] 3.1 In `UpdateChecker::check()`, capture `published_at` from the `fetchLatest()` payload as `$latestPublishedAt`. When `$installedVersion` equals `$payload['latest']` (i.e. installed == latest), populate `$installedVersionReleasedAt` from this captured value with no extra HTTP call.
- [x] 3.2 When installed differs from latest, call `$this->client->fetchReleaseByTag('v' . $installedVersion)`. GitHub release tags are stamped as `vX.Y.Z` (see `.github/workflows/release.yml`'s `v[0-9]+.[0-9]+.[0-9]+*` tag filter and `bin/release`'s `${GITHUB_REF_NAME#v}` stripping), while `$installedVersion`/the `VERSION` file are always unprefixed — the `v` must be re-added before querying `releases/tags/<tag>`, otherwise the lookup 404s for every install that isn't exactly on the latest tag. On success, populate `$installedVersionReleasedAt` from the result. On failure (including missing method on a subclass that hasn't been updated), leave the field `null` and continue — the check must not throw.
- [x] 3.3 When `$this->client->githubRepo() === ''`, persist the existing "up to date" sentinel with `installedVersionReleasedAt = null` and skip both HTTP calls.
- [x] 3.4 Update `buildUnknownResult()` and `rehydrateCached()` to carry `installedVersionReleasedAt` through the cached / unknown paths.
- [x] 3.5 Add unit tests in `tests/Unit/Update/UpdateCheckerTest.php`: installed == latest uses `published_at` from `fetchLatest()`, installed != latest calls `fetchReleaseByTag()` with a `v`-prefixed tag (assert the exact argument, e.g. installed `1.2.3` → `fetchReleaseByTag('v1.2.3')`) and merges the date, `fetchReleaseByTag()` failure leaves the field `null` and does not throw, no-repo-configured path sets `installedVersionReleasedAt = null` and makes no HTTP calls, cached result round-trips the new field.
